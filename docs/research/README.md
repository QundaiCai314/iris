# Iris 研究库（Research Log）规范

> 原则：学习和研究一定要多做；每项研究都按规范落到项目文档；宁可先查证、后定参，不拍脑袋。

## 1. 文件与编号
- 存放：docs/research/，文件名 R<编号>-<英文短名>.md（编号两位数顺序递增）。
- 每篇必须含元信息块（编号 / 日期 / 状态 / 研究问题 / 一句话结论），正文按：结论先行 → 方法与证据 → Iris 落地映射 → 局限 → 来源。

## 2. 引用与证据规范
- 同行评审文献：作者（年）标题，期刊 / DOI / URL。
- 非同行评审（媒体、平台统计、工作论文、讲座）：必须显式标注来源性质，结论只取「量级 / 方向」，不给假精度。
- 禁止编造出处；查不到的写「待核实」；产品决策引用研究用 Rnn §小节 格式。
- 每条经验结论尽量给出「可证伪条件」（什么情况下它不成立）。

## 3. 状态流转
草案（新写）→ 评审（用户 / 答辩前过一遍）→ 定稿（可被代码引用为决策依据）。状态更新需改元信息块与下方索引。

## 4. 研究到代码的路径
定稿研究才能进 product-spec 与引擎参数；代码中引用处注释 Rnn（例：// 代理先验曲线: R02 §3）。代码评审时发现「参数无出处」= bug。
