# R05 需求澄清参数化：必需分流与等待贴现

- 编号 / 日期：R05 / 2026-09-04
- 状态：定稿（2026-09-06，已被引擎参数引用）
- 研究问题：问卷答案如何变成模型参数（必需 / 可选分流、等待成本 U、P2 的概率换算），而不是靠 agent 感觉打分？
- 一句话结论：必需 / 可选沿用经济学的弹性操作化（收入弹性低者偏必需），类目规则 + 弹性探针双保险；「等待意愿」必须用多组「时长 x 折扣」离散选择题反推个人贴现档位——人对等待的报价是双曲 / 框架依赖的，直接问利率或「能等吗」都会失真；享乐型商品（显卡）等待成本系统性更高。

## 1. 必需 vs 可选：经济学的操作化
- 自 Engel（1895）起，必需 / 奢侈品的经验定义是收入弹性 < 1 vs > 1（综述：Beyond Engel's Law，Journal of Socio-Economics，2013）；奢侈品通常价格弹性也更大（英国最低工资影响综述：Aitken, Dolton & Wadsworth，HMT 文件）。标准估计框架是 Deaton & Muellbauer（1980）需求系统。
→ Iris 的「必需闸门」两层实现：
  1. 类目规则：药、医疗、基础食品、通勤 / 学业必需品等低收入弹性类目 → 默认只做渠道比价、不跑时机引擎；
  2. 弹性探针（问卷兜底）：「如果价格翻倍，你还会买 / 马上买吗」——答「照样买」= 必需，答「换 / 等」= 可选。
  分流依据有出处，不靠 agent 自由心证。

## 2. 为什么「等待意愿」不能直接问
- 隐含贴现率高得离谱：肯尼亚现金转移实验的 willingness-to-wait 隐含年贴现率约 64%~536%（EDCC，2020）——人对「等待」的报价远非线性。
- 框架依赖：同一批被试可以在「延迟获得收益」与「提前支付成本」两种框架下给出矛盾选择（Eil 等，NYU CESS 工作论文，hyperbolic vs hypobolic discounting），即不存在能同时解释两个框架的单一贴现率。
- 享乐调节：享乐型消费的等待贴现衰减更快（Calgary 存档研究，三组实验），即越「想要」等得越难受。
→ 对 Iris：用户说「能等」不等于真能等；问卷若直接问「能接受等几个月」会把自欺当参数。

## 3. 问卷落地（代码引用 R05 §3）
- 不问年化利率，给 3~4 道离散选择题（如：A 现在 5000 / B 等 2 个月 4700 / C 等 6 个月 4300 / D 等 12 个月 3800），用「匹配法」把用户归入低 / 中 / 高三档贴现；
- 档位映射到 U（等待期效用损失）与「期望节省换算系数」；
- 使用强度（每周使用小时 / 场景权重）单独问，进效用损失；
- 享乐 / 实用标签（品类规则 + 用户自评）对等待成本乘调节系数（享乐品上浮，方向来自 R05 §2.3，系数待 B05 问卷实验标定）。
- 用户自评「能不能等」只作先验展示，最终参数以离散选择题答案为准。

## 4. 局限与待办
- 上述贴现率实证多来自发展中国家或特殊样本，绝对数值不可直接套用——只取「非线性、框架依赖、享乐衰减」的结构性结论，档位阈值需 B05 小样本自测标定；
- 商品类目的收入弹性是宏观量级，具体商品可能偏离 → 保留弹性探针兜底；
- P2（含效用的最优决策概率）的所有效用参数必须随建议一起展示，用户可调（总纲 2.5 透明原则）。
